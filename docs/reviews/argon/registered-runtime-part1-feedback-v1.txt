## 3. Smallest Useful Cooperative Runtime Slice (Zero Paid Calls)

### 3.1 Why Existing Paths Are Incomplete on Their Own
Currently, Dojo has three disconnected offline/development execution paths and one passive journal:
1. **`runner.run_demo` (`dojo/bench/runner.py`):** Uses `ResultStore` (schema v3), `ScriptedTransport`, and `FakeSandbox`. It neither reserves promotional credits in `CreditLedger`, nor binds Stage B `execution_intent` bytes, nor restores hidden tests or runs candidate scoring.
2. **`owned_adaptive.run_owned_rehearsal` (`dojo/solve/owned_adaptive.py`):** Uses `BindingStore` (schema v4), `CreditLedger`, `ScriptedWireTransport`, and `FakeSandbox`. It coordinates per-turn `before_send` (`begin_fake_send`) and `after_response` (`record_known_response`) against `CreditLedger`, **but stops at the end of the solver loop**: it never extracts a candidate archive, never restores hidden tests via `prepare_candidate_reference`, never executes or judges scoring receipts, and cannot run `DockerSandbox`.
3. **`flow_development.run_case` (`dojo/eval/flow_development.py`):** Uses `ScriptedModel`, `DockerSandbox`, and `docker_scoring_v2.run_development_score` on `contract_development.fixture(repo)`. It exercises real Docker edits, hidden-test restoration, and scoring, **but has zero persistence, zero `Claim`/lease ownership, zero `execution_intent` verification, zero `CreditLedger` reservation/settlement, and zero wire-codec (`nebius_codec`) validation**.
4. **`ObservationStore` (`dojo/store/observations.py`, schema v6):** Validates and records the full 7-stage hash-chained lifecycle (`reservation_intent` -> `reservation_bound` -> `request_intent` -> `response_known` -> `candidate` -> `scoring` -> `settled` / `uncertain`), **but is purely a passive store** called manually in `tests/test_observation_journal.py`. No runtime coordinator drives it!

### 3.2 Design of the Owned Runtime Bridge Coordinator (`dojo/bench/runtime_bridge.py`)
The smallest useful cooperative runtime slice is a host-owned coordinator (`dojo/bench/runtime_bridge.py`) that drives **`ObservationStore` (schema v6)** + **`CreditLedger`** + **wire-validated model turns (`nebius_codec` + `ScriptedWireTransport`)** + **sandbox execution (`FakeSandbox` for unit tests or `DockerSandbox` for synthetic local Docker rehearsal)** + **protected hidden-test restoration (`prepare_candidate_reference`)** + **phase-aware scoring (`assess_candidate` + `baseline_is_operational` via `docker_scoring_v2` or deterministic fake scorer in unit tests)** + **terminal ledger/store settlement (`finish_run` + `finish_known` / `close_uncertain`)**.

#### Key Architectural Decisions in the Slice:
1. **Host Runtime Owns Adapters and Ordering:**
   - Callers cannot pass pre-acquired `Claim` objects, pre-opened `reservation_id` strings, custom callback hooks, or unverified raw receipts.
   - The coordinator owns the exact ordering of every database transaction and external action:
     1. Verifycoordinator source integrity (`_sources()`) and separate SQLite paths (`store.path.resolve() != ledger.path.resolve()`).
     2. Claim cell & bind immutable `execution_intent` (`store.claim_cell(...)` + `store.verify_cell(...)`).
     3. Pre-validate `RunSettings`, `PricingSnapshot`, `prompt_unit_bound`, and initial `ModelRequest` wire payload; compute whole-run conservative reservation `amount = _ceil_request_cost_nano_usd(prompt_unit_bound, reply_tokens, pricing) * max_steps`.
     4. Record `store.begin_reservation(claim, ledger, amount, now=now())` **before** mutating `CreditLedger`.
     5. Reserve in `CreditLedger`: `reservation_id = ledger.reserve_run(_nano_usd_to_plain_usd(amount), now=now())`.
     6. Bind reservation in `ObservationStore`: `store.bind_reservation(claim, ledger, reservation_id, now=now())`.
     7. Start sandbox (`sandbox.start(view.source_archive)`).
     8. Execute bounded turn loop (`1..max_steps`):
        - Check monotonic wall clock (`timer.remaining() > 0`) and recheck `_sources() == initial_sources`.
        - Build `ModelRequest` with `timeout_seconds = min(command_timeout_seconds, remaining)`.
        - Check `fictional_prompt_units(messages) <= prompt_unit_bound`, `prompt_unit_bound + reply_tokens <= context_tokens`, and cumulative token/cost bounds.
        - Persist `store.request_intent(claim, ledger, request, prompt_unit_bound, now=now())` **before** calling `transport.send(...)`.
        - Call `transport.send(wire_payload, timeout_seconds=request.timeout_seconds)`.
        - Validate HTTP status (`200 <= status_code < 300`) and record `store.response_observation(claim, ledger, request, response.body, now=now())` **before** acting on assistant content.
        - Decode via `decode_completion(response.body, request)`: if `status in {'unusable', 'truncated'}`, stop the solver turn loop cleanly with known usage (`stop_reason='content_unusable'` or `'output_limit'`).
        - Parse action via `parse_action(observation.content)`:
          - If `None`: append `Message('user', FORMAT_FEEDBACK)`, increment `invalid_turns`, continue next turn.
          - If `('finish', None)`: mark `done=True`, `stop_reason='self_reported_done'`, break loop.
          - If `('bash', command)`: verify `timer.remaining() > 0`, execute `sandbox.execute(command, timeout=min(command_timeout_seconds, remaining))`, append `Message('user', observation_text)`.
        - Assert `flow_development.assert_agent_boundary(messages, contract.fail_to_pass)` on every turn so evaluator-only data can never enter solver observations.
     9. Candidate & Scoring Phase (only when solver loop finishes with known usage and `not sandbox.failed`):
        - Export `candidate_archive` (`snapshot_archive(sandbox.current)` for `DockerSandbox`, or applied-patch snapshot for `FakeSandbox`) and `patch = sandbox.patch`.
        - Record `store.candidate_observation(claim, candidate_archive, patch, now=now())` (which runs `prepare_candidate_reference(contract, candidate_archive, patch)`).
        - Run scoring adapter (either real Docker `docker_scoring_v2._execute` on ` synthetic_` fixtures or a predeclared `FakeScoringAdapter` for offline unit tests) to obtain `envelope_raw` and optional `baseline_raw` (when `assess_candidate` returns `'requires_baseline'`).
        - Record `store.scoring_observation(claim, envelope_raw, baseline_raw=baseline_raw, now=now())`.
     10. Settlement Phase:
        - Call `ledger.finish_run(reservation_id, _nano_usd_to_plain_usd(known_cost))`.
        - Call `store.finish_known(claim, ledger, now=now())`.
2. **Bridging `ObservationStore` to Synthetic Local Fixtures Without Paid Calls or Falsifying Stage B Artifacts:**
   - Why this matters: `ObservationStore.claim_cell` calls `bound_plan.prepare_bound_plan(directory, task_id, config_id, seed)` and `execution_intent.build_intent(directory, task_id, config_id, seed)`, and `candidate_observation` / `scoring_observation` call `scoring_contract.load_contract(task_id)`. Meanwhile, `docker_scoring_v2.run_development_score` refuses non-`synthetic_` task IDs (`if not contract.task_id.startswith('synthetic_'): raise ValueError(...)`).
   - How the coordinator supports **both** without modifying `ObservationStore` or unlocking real tasks:
     - **Mode A — Offline Unit / Contract Rehearsal (`FakeSandbox` + `FakeScoringAdapter`):** Can run against a synthetic cell fixture directory (or monkeypatched `prepare_bound_plan`/`build_intent`/`load_contract` in unit tests, exactly as `tests/test_observation_journal.py` does) with zero Docker and zero network calls.
     - **Mode B — No-Network Synthetic Local Rehearsal (`DockerSandbox` + `docker_scoring_v2` on `contract_development.fixture`):** For the synthetic fixture task (`synthetic_method-subtests-v2` or `synthetic_legacy-v1`), the coordinator provides a dedicated `prepare_synthetic_cell_bundle(tmp_dir, repo, config_id, seed)` helper (or `SyntheticCellContext`) that binds `contract_development.fixture(repo)` into a self-contained synthetic `BoundPlan` and `execution_intent` bytes with `evidence_kind='synthetic'` and `execution_authorized=False`, allowing `ObservationStore` to execute the entire 7-event SQL chain (`reservation_intent` -> `reservation_bound` -> `request_intent` -> `response_known` -> `candidate` -> `scoring` -> `settled`) end-to-end with real isolated Docker containers (`DockerSandbox` + `docker_scoring_v2`) and zero provider calls!
3. **Strict Separation of Scripted Model Evidence from Actual Docker/Scorer Evidence:**
   - In any run using `ScriptedWireTransport`, model replies and token counts are synthetic/scripted (`provider_calls=0`, `provider_evidence_verified=False`, `model_evidence_kind='scripted_wire_rehearsal'`), even when `sandbox` and `scorer` execute real local Docker containers (`sandbox_evidence_kind='local_docker'` vs `'fake_sandbox'`, `scoring_evidence_kind='local_docker_cooperative'` vs `'fake_scorer'`).
   - The coordinator's result summary explicitly separates these three evidence dimensions (`model_evidence_kind`, `sandbox_evidence_kind`, `scoring_evidence_kind`) while keeping top-level `evidence_kind='unverified_diagnostic'` (or `'synthetic'`), `registration_verified=False`, `publishable=False`, and `counts_toward_benchmark=False`.

## 4. Genuine-Run Provenance Requirements vs. Cooperative Boundaries

1. **Why Digests, DTO Flags, and Callbacks Are Not Registration Approval:**
   - `RegistrationDraft.fingerprint()`, `execution_intent.check_intent()`, `ObservationStore` event hash chains (`event_sha256`), and `_sources()` file SHA-256 maps prove **internal data consistency** on a cooperative host checkout. They do **not** prove external authenticity against an adversarial host operator, nor do they constitute Stage B registration sign-off.
   - All summary methods must hardcode `registration_verified: False`, `execution_authorized: False`, `provider_evidence_verified: False`, `publishable: False`, `live_enabled: False`, and `counts_toward_benchmark: False`.
2. **Source & Artifact Provenance Requirements Before, During, and After Execution:**
   - **Pre-Claim:** `verify_workspace(directory)` must confirm that on-disk Stage B JSON artifacts match fresh host reconstruction (`build_workspace_artifacts()`), and `_sources()` must record the SHA-256 of every coordinator, solver, provider-codec, store, and evaluator Python file.
   - **Per-Turn / Pre-Dispatch:** Immediately before every `request_intent` and before `candidate_observation` / `scoring_observation`, the coordinator must re-verify `_sources() == initial_sources` and `store.verify_cell(claim, ...)`. Any mid-run file modification or artifact drift immediately aborts and fences the attempt as `'uncertain'`.
   - **Image Identity Provenance:** Currently, `registration_preflight.py` records `identity_status: 'configured_uninspected'`. For a genuine run (Task `4j`), the host must inspect the local Docker daemon (`docker image inspect <image_id> --format {{.Id}}`) and verify exact digest equality with `solver_image['image_id']` and `scoring_image['image_id']` before claiming or dispatching.
   - **Candidate & Restoration Provenance:** `candidate_observation` must verify `make_patch(original_files, candidate_files) == patch` and compute `prepared_sha256 = sha256(prepare_candidate_reference(contract, candidate_archive, patch))`. The scoring container must execute **only** the bytes matching `prepared_sha256`.
   - **Baseline Attribution Provenance:** Under `ERROR_POLICY = 'complete-panel-baseline-attributed-candidate-errors-v1'`, any candidate receipt that yields `assess_candidate(...).status == 'requires_baseline'` (`install` failure, pytest `collection` error with exit 2/5, or `setup_or_teardown` error) **cannot** be recorded as `'candidate_error'` (`'unsolved'`) unless a fresh execution of `contract.restored_archive` on the same `contract.image_id` satisfies `baseline_is_operational(contract, baseline_envelope, image_id=contract.image_id) == True`. Both `envelope_sha256` and `baseline_sha256` must be bound in the `scoring` observation event.
3. **Honest Scope of Cooperative Score Collection:**
   - As recorded in `SCORER_SCOPE = 'cooperative-python-not-adversarially-authenticated-v1'`, candidate Python code and `pytest` share an interpreter inside the scoring container (`UID 65534`). While `docker_scoring_v2.STREAMS` isolates OS FDs 1 and 2 (`os.dup(1)` + `os.dup2` to `/dev/null`) against accidental stdout noise, malicious candidate Python code can still monkeypatch `pytest` in memory. Therefore, scoring receipts must be labeled `cooperative_unauthenticated` and never described as cryptographically or adversarially authenticated.

## 5. Transaction, Crash, Concurrency, and Cleanup Matrix

Neither SQLite (`ObservationStore` on `store.path` and `CreditLedger` on `ledger.path`) nor external side effects (wire transport dispatch and Docker container execution) support distributed two-phase commit. Therefore, every boundary is ordered **fail-closed** so that any crash, exception, clock anomaly, or lease expiration fences both the attempt and the credit reservation into `'uncertain'`, permanently blocking automatic retry or budget reuse.

| Boundary / Window | DB / External State Before Step | Failure / Crash / Anomaly Mode | Recovery & Fencing Action by Coordinator | Resulting `ObservationStore` State | Resulting `CreditLedger` State | Retry / Subsequent Run Eligibility |
|---|---|---|---|---|---|---|
| **B1. Pre-Claim Validation** | No `runs` row; no `reservations` row. | Invalid settings/pricing/bounds, changed source files, or `store.path == ledger.path`. | Raise `BridgeError` / `PreflightError` / `ValueError` before touching DB or ledger. | Unchanged (no row). | Unchanged (no row). | Eligible after fixing caller input. |
| **B2. Claim & `execution_intents` Insert** | `claim_cell` opens `BEGIN IMMEDIATE`. | Crash or `StoreError` after `super().claim()` before `INSERT INTO execution_intents` commits. | `claim_cell` catches `(StoreError, sqlite3.Error)` and calls `self.block(claim, now=now)`. | `runs.execution_state = 'uncertain'`, `stop_reason = 'unknown_execution'`. | Unchanged (no reservation). | **Blocked.** `one_unresolved_attempt` index and `AttemptStore.claim` check block all new non-synthetic claims until manual review. |
| **B3. `begin_reservation` (`reservation_intent`)** | `runs.execution_state = 'running'`; no ledger reservation yet. | Crash or `StoreError` (e.g., `ledger.status()['can_reserve']` is False, or prior `reservation_intent` on same `ledger_key` is not `'settled'`). | Coordinator catches error and calls `store.close_uncertain(claim, now=now())` (with fallback to `store.block(claim)`). | `observation_events` ends in `'uncertain'`; `runs.execution_state = 'uncertain'`, `run_context.reservation_state = 'intent_pending'` (if `begin_reservation` committed). | Unchanged (no reservation row created). | **Blocked.** Unsettled `reservation_intent` on `ledger_key` blocks future `begin_reservation` calls in `ObservationStore`. |
| **B4. `ledger.reserve_run` -> `store.bind_reservation` Window** | `reservation_intent` committed in `ObservationStore`; `ledger.reserve_run` inserts `reservations(state='pending')`. | Crash, power loss, or `StoreError` **after** `ledger.reserve_run` commits but **before** `store.bind_reservation` commits. | In-process `except BaseException:` calls `ledger.finish_run(reservation_id, None)` and `store.close_uncertain(claim, now=now())`. If hard process death (SIGKILL), `reservations.state` remains `'pending'` and `observation_events` remains at `'reservation_intent'`. | `'uncertain'` (if caught) or `'running'` with expired lease + unresolved `'reservation_intent'` (if SIGKILL). | `'uncertain'` with `policy.blocked = 1` (if caught) or `'pending'` (if SIGKILL). | **Blocked in both DBs.** `CreditLedger.reserve_run` refuses when any row has `state != 'completed'`; `ObservationStore.begin_reservation` refuses when any prior run on `ledger_key` is not `'settled'`. |
| **B5. Per-Turn `request_intent` (Pre-Send)** | `stage` is `'bound'` or `'answered'`; `reservations.state = 'pending'`. | Lease expired (`OwnershipError`), clock regression, source drift, deadline remaining `< timeout_seconds`, or `ledger.check_run` fails (observation age `>= 1h` or expiry `< 24h`). | Do **not** call `transport.send`. Call `ledger.finish_run(reservation_id, None)` and `store.close_uncertain(claim, now=now())`. | `stage = 'uncertain'`, `runs.execution_state = 'uncertain'`. | `reservations.state = 'uncertain'`, `policy.blocked = 1`. | **Blocked.** Zero network/wire requests were dispatched on the failed turn, and prior turns' uncertain state is fenced. |
| **B6. Wire Dispatch (`transport.send`)** | `request_intent` (ordinal $2k+1$) committed in `ObservationStore`. | `transport.send` raises `TimeoutError` or `Exception`, returns non-2xx HTTP status, or crashes mid-flight. | Never retry. Call `ledger.finish_run(reservation_id, None)` and `store.close_uncertain(claim, now=now())`. | `stage = 'uncertain'` (`request_intent` has no matching `response_known`). | `reservations.state = 'uncertain'`, `policy.blocked = 1`. | **Blocked.** Ambiguous dispatch is never replayed. |
| **B7. `response_observation` Validation** | `transport.send` returned 2xx bytes `raw`. | `decode_completion` raises `CodecError`, returns `status == 'unknown_usage'`, `model_matches == False`, token overrun (`prompt_tokens > prompt_bound` or `completion_tokens > reply_bound`), or cost overrun. | `ObservationStore.response_observation` automatically calls `self.close_uncertain(claim, now=now)` and raises `StoreError`. Coordinator then calls `ledger.finish_run(reservation_id, None)`. | `stage = 'uncertain'`, `runs.execution_state = 'uncertain'`. | `reservations.state = 'uncertain'`, `policy.blocked = 1`. | **Blocked.** Unknown or out-of-bound usage permanently blocks ledger. |
| **B8. Known-Usage Early Solver Stop (`unusable` / `truncated` / `step_cap` / `token_cap` / `deadline` / `sandbox_error`)** | All dispatched requests have matching `response_known` events (`stage == 'answered'`). | Solver stops early because model reply is `'unusable'`/`'truncated'`, or controller hits `step_cap`/`token_cap`/`deadline`, or `sandbox.execute` times out / fails. | Wait: Look at `ObservationStore._reduce`! In `ObservationStore._reduce`, `'settled'` **strictly requires** `state['stage'] == 'scored'`, which requires `'candidate'` and `'scoring'`! If `sandbox.failed` is True (e.g., solver container timeout or cleanup failure) so no valid candidate workspace exists to score, the run **cannot** transition to `'candidate'` -> `'scored'` -> `'settled'`. It must call `store.close_uncertain(claim, now=now())` and `ledger.finish_run(reservation_id, None)` (or if candidate workspace is intact on `step_cap`/`truncated`, export candidate, score it, and settle known cost!). | If candidate workspace is valid and scored: `stage = 'settled'`. If `sandbox.failed` or scoring incomplete: `stage = 'uncertain'`. | If scored & settled: `state = 'completed'`, `usage = state['cost']`. If incomplete/unscored: `state = 'uncertain'`, `blocked = 1`. | **Critical finding from `_reduce`:** `ObservationStore` only permits `settled` after `scored`. Any run that aborts before `scoring` must close as `uncertain`. |
| **B9. Candidate Restoration & Scoring (`candidate_observation` / `scoring_observation`)** | `stage == 'answered'`; solver loop finished with valid workspace. | Patch tampering (`make_patch(orig, cand) != patch`), container crash/timeout during scoring, fabricated/malformed receipt (`CodecError`/`PreflightError`), or `requires_baseline` with missing/unhealthy baseline (`baseline_is_operational == False`). | Do **not** settle. Call `ledger.finish_run(reservation_id, None)` and `store.close_uncertain(claim, now=now())`. | `stage = 'uncertain'`, `runs.execution_state = 'uncertain'`. | `reservations.state = 'uncertain'`, `policy.blocked = 1`. | **Blocked.** |
| **B10. Terminal Settlement (`ledger.finish_run` -> `store.finish_known`)** | `stage == 'scored'`; `known_cost == state['cost']`. | `ledger.finish_run(reservation_id, usd_str)` succeeds (`reservations.state = 'completed'`), then `store.finish_known` fails (e.g. lease expired at the exact microsecond before `finish_known`). | Coordinator catches `StoreError` from `finish_known` and calls `store.close_uncertain(claim, now=now())` (which sets `expired_ok=True` in `_owned`!). | `stage = 'uncertain'` (`expired_ok=True` allows `close_uncertain` even after lease expiry!). | `reservations.state = 'completed'`, `usage = state['cost']`. | **Blocked in `ObservationStore`** (terminal event is `'uncertain'`, not `'settled'`, so `begin_reservation` refuses subsequent runs on `ledger_key` until manual inspection). |
| **B11. Container Cleanup (`finally` blocks in `DockerSandbox` & `docker_scoring_v2`)** | Container `dojo-solver-<uuid>` or `dojo-candidate-score-<uuid>` started. | `docker rm --force <name>` times out (`> 5s`), raises `OSError`, or exits non-zero (other than `No such container`). | Sets `sandbox.failed = True`, raises `RuntimeError('... cleanup failed; stop')`, which triggers coordinator `except BaseException:` -> `ledger.finish_run(reservation_id, None)` + `store.close_uncertain(claim, now=now())`. | `stage = 'uncertain'`. | `reservations.state = 'uncertain'`, `policy.blocked = 1`. | **Blocked.** Post-run `check_clean()` also verifies zero lingering `dojo-solver-*` or `dojo-candidate-score-*` containers. |

## 7. Minimal Interface Assessment: Can Integration Proceed Safely Without Editing Existing Files?

**Yes.** A careful audit of all 24 allowlisted files in `context.md` confirms that **zero edits to existing files are required** to implement the cooperative runtime bridge in Part 2, provided the new coordinator module (`dojo/bench/runtime_bridge.py`) includes two small internal adapters:

1. **Scoring Envelope + Baseline Capture Adapter (`_score_candidate_with_baseline_bytes`):**
   - *Why needed:* `docker_scoring_v2.run_development_score` returns `CandidateScore(..., baseline_verified: bool, envelope: dict)`, which discards the raw `baseline` receipt dict after checking `baseline_is_operational(contract, baseline, image_id=contract.image_id)`. Meanwhile, `ObservationStore.scoring_observation(claim, envelope_raw, *, baseline_raw=None, now)` requires the canonical JSON `bytes` of **both** `envelope` and `baseline` whenever `assess_candidate` returns `'requires_baseline'`.

2. **Synthetic Rehearsal Cell Context Adapter (`SyntheticCellBundle`):**
   - *Why needed:* `IntentAttemptStore.claim_cell` and `ObservationStore.candidate_observation` / `scoring_observation` call `prepare_bound_plan(directory, task_id, config_id, seed)`, `build_intent(directory, task_id, config_id, seed)`, and `load_contract(task_id)`. ## 3. Explicit Uncertainty & Constraints List

1. **`ObservationStore._reduce` Terminal State Constraint on Unscored Stops:**
* In `dojo/store/observations.py`, `_reduce` enforces `if state["stage"] != "scored" or p["cost"] != state["cost"]: raise StoreError("Settlement does not cover complete observed history")`.
* Consequently, even if every dispatched model request received a valid `response_known` observation (so model token usage is known), **an attempt in `ObservationStore` cannot be marked `'settled'` unless it also completes `'candidate'` and `'scoring'**`.
* *Design Resolution:*
* If the solver loop stops early with known usage while the sandbox workspace is still valid (e.g., `step_cap`, `token_cap`, `context_cap`, `output_limit` truncation, or `content_unusable` after a valid `response_known`), the coordinator **can still export `sandbox.current` and `sandbox.patch`, record `candidate_observation`, run `scoring_observation`, and settle known usage (`settled`)** — provided the model did not fail with `unknown_usage` and `sandbox.failed` is `False`.
* Conversely, if `sandbox.failed` is `True` (e.g., `DockerSandbox` command timeout or container error leaves partial workspace discarded), `flow_development.py` establishes the invariant: *incomplete solver state must never reach scoring*. Therefore, when `sandbox.failed` is `True`, the coordinator skips candidate/scoring and closes the run via `close_uncertain` and `ledger.finish_run(reservation_id, None)`.
* **Question for Primary Review:** Confirm whether you want known-usage non-`finish` solver stops (`step_cap`, `output_limit`, `content_unusable`) when `not sandbox.failed` to proceed through `candidate` -> `scoring` -> `settled`, or whether any stop other than `self_reported_done` should skip scoring and close as `uncertain`.




2. **Synthetic Cell Binding vs. Stage B Workspace Verification:**
* `IntentAttemptStore.claim_cell` calls `bound_plan.prepare_bound_plan` and `execution_intent.build_intent`, which call `registration_preflight.verify_workspace(directory)` (checking the 63 repository tasks). Meanwhile, `docker_scoring_v2.run_development_score` only allows `contract.task_id.startswith('synthetic_')`.
* *Design Resolution:* In Part 2, `runtime_bridge.py` will support both:

A dedicated `SyntheticCellAdapter` (for the no-network synthetic demo script and optional local Docker rehearsal) that builds a self-consistent synthetic `BoundPlan` and `execution_intent` for `contract_development.fixture('more-itertools/more-itertools')` (`task_id='synthetic_method-subtests-v2'`) without touching the 63-task Stage B panel or local Git clones.
