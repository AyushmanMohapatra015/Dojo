# Dojo Benchmark Statistics & Cold-Restart Cascade Methods Reference (WP1–WP10)

## 1. Scope, Boundaries, and Non-Claims

This document defines the complete mathematical specification for Dojo's offline benchmark statistics and cold-restart cascade analysis subsystem (`dojo/bench/` and `dojo/cascade/`).

- **Synthetic & Unverified Status:** Every example and fixture in the current repository is synthetic. All reports generated by this subsystem carry `EligibilityStatus(status="UNVERIFIED", publishable=False, development_only=True)`. Non-null `registration_id` strings or `"real"` evidence labels never automatically grant publication approval; Stage B registration and real held-out governance require a separate trusted verifier.
- **Owner Learning Requirement (16c):** This reference implementation satisfies software tasks 9a–9h and does not complete or substitute for the project owner's handwritten mathematical explanation and exercise in task 16c.
- **Zero Provider / Cache Coupling:** All runtime modules use Python's standard library only, operate strictly on validated normalized JSON envelopes, and never invoke LLM providers, Docker containers, databases, or shell commands.

## 2. Normalized Panel Validation and Scorer Status Rules (WP1)

An analysis input envelope declares an `ExpectedPlan` with ordered tasks $T = (t_1, \dots, t_n)$ and configuration seed lists $S_c = (s_{c,1}, \dots, s_{c,k_c})$ for each configuration $c \in C$. A valid panel requires exact 1-to-1 coverage of all expected cells:

$$\mathcal{E} = \{ (c, t, s) \mid t \in T,\; c \in C,\; s \in S_c \}, \quad |\mathcal{E}| = n \sum_{c \in C} k_c$$

| `scorer_status` | Required `outcome` | Required `evidence_validity` | Additional Requirement | Headline Treatment |
|---|---|---|---|---|
| `passed` | `solved` | `valid` | `execution_complete = True` | Valid solved ($y_{c,t,r} = 1$) |
| `failed` | `unsolved` | `valid` | `execution_complete = True` | Valid unsolved ($y_{c,t,r} = 0$) |
| `candidate_error` | `unsolved` | `valid` | `baseline_verified = True` and `execution_complete = True` | Valid unsolved ($y_{c,t,r} = 0$) iff `baseline_verified=True`; otherwise **blocked** |
| `invalid_evidence` | `undetermined` | `invalid` | — | **Blocked** (`audit.status = "blocked"`) |
| `infrastructure_error` | `undetermined` | `unknown` | — | **Blocked** (`audit.status = "blocked"`) |

Missing cells, duplicate cells, unexpected cells, mixed splits (`train` mixed with `held_out`), or conflicting task `family_id` assignments block headline metrics (`summary_mode = "blocked"`). Missing `cost_nano_usd` values set `audit.status = "cost_incomplete"`, blocking cost comparisons and frontiers while permitting an explicitly labeled `summary_mode = "success_only"` report when `--allow-success-only` is requested.

## 3. Primary Estimands and Cost Semantics (WP2)

For configuration $c$ with $k_c = |S_c|$ declared seeds on each of the $n = |T|$ tasks, let $y_{c,t,r} \in \{0, 1\}$ be the binary solve indicator and $\text{cost}_{c,t,r} \in \mathbb{Z}_{\ge 0}$ be the measured cost in integer nano-USD ($10^{-9}\text{ USD}$).

1. **Per-task mean success rate and mean 1-seed cost:**
   $$p_{c,t} = \frac{1}{k_c} \sum_{r \in S_c} y_{c,t,r}, \qquad m_{c,t} = \frac{1}{k_c} \sum_{r \in S_c} \text{cost}_{c,t,r}$$
2. **Equal-task-weighted $\text{pass@1}$ and expected solved tasks:**
   $$\text{pass@1}(c) = \frac{1}{n} \sum_{t \in T} p_{c,t}, \qquad S_{\text{exp}}(c) = \sum_{t \in T} p_{c,t} = n \cdot \text{pass@1}(c)$$
3. **Expected 1-seed total cost and mean task cost:**
   $$C_{\text{exp}}(c) = \sum_{t \in T} m_{c,t}, \qquad \bar{m}(c) = \frac{1}{n} C_{\text{exp}}(c)$$
4. **Expected cost per solved task (`expected_cost_per_solved_nanos`):**
   $$\text{CPS}(c) = \begin{cases} \dfrac{C_{\text{exp}}(c)}{S_{\text{exp}}(c)} = \dfrac{\sum_{t \in T} m_{c,t}}{\sum_{t \in T} p_{c,t}} & \text{if } S_{\text{exp}}(c) > 0 \\[8pt] \text{UndefinedValue}(\texttt{"zero\_expected\_solves"}) & \text{if } S_{\text{exp}}(c) = 0 \end{cases}$$
   All failed runs' measured costs remain in $C_{\text{exp}}(c)$.
5. **Actual all-repetition spend (`actual_all_repetitions_spend_nanos`):**
   $$C_{\text{actual}}(c) = \sum_{t \in T} \sum_{r \in S_c} \text{cost}_{c,t,r}$$
   This is the total historical spend across all repetitions $k_c$ and is **never** divided by single-seed expected solves $S_{\text{exp}}(c)$.

All intermediate arithmetic uses exact `fractions.Fraction` and `int` values, avoiding binary floating-point drift and ambient `Decimal` context mutation.

## 4. Paired Task Bootstrap and Zero-Solve Draw Accounting (WP3)

- **Shared Task Resampling:** In each replicate $b \in \{1, \dots, B\}$ (default $B = 10,000$, using an isolated `random.Random(seed)`), $n$ task indices $I^{(b)} = (i^{(b)}_1, \dots, i^{(b)}_n)$ are drawn uniformly with replacement from $\{0, \dots, n-1\}$. Every configuration and cascade series is evaluated on the **identical** task multiset $I^{(b)}$, retaining all seeds of each sampled task.
- **Empirical Quantiles (Hyndman-Fan Type 7 over `Fraction`):** For $B$ sorted draws $x_{(0)} \le \dots \le x_{(B-1)}$ and quantile $q \in [0, 1]$:
  $$h = q(B - 1), \quad \ell = \lfloor h \rfloor, \quad u = \lceil h \rceil, \quad Q(q) = x_{(\ell)} + (h - \ell)\bigl(x_{(u)} - x_{(\ell)}\bigr)$$
- **Zero-Solve Draws:** If any bootstrap replicate $b$ has zero expected solves ($S^{*(b)}_{\text{exp}} = 0$), $\text{CPS}^{*(b)}$ is undefined. The engine records the exact count in `zero_solve_draws` and `undefined_draws` and blocks the unconditional confidence interval endpoints (`lower = upper = UndefinedValue("unconditional_interval_blocked_by_zero_solve_draws")`) rather than silently dropping zero-solve draws to fabricate a conditional interval.

## 5. Non-Primary Sensitivity Analyses (WP4)

1. **Family-Cluster Bootstrap (`family_cluster_bootstrap`):** Resamples $M$ distinct `family_id` clusters with replacement, includes every task in each selected cluster occurrence (retaining all seeds), and weights included task occurrences equally (`is_primary = False`). Because the resampled task count $n^{*(b)}$ varies when cluster sizes are unbalanced, total-cost intervals preserve the original $n$-task scale via $\hat{C}^{*(b)}_{\text{target-}n} = n \cdot \bar{m}^{*(b)}$ and report `min_resampled_tasks`, `max_resampled_tasks`, and `mean_resampled_tasks`.
2. **Seed-Position and Subset Sensitivity (`seed_sensitivity_analysis`):** Evaluates predeclared ordinal seed positions (`0 .. min_c k_c - 1`), `shared_exact_seeds`, and explicit seed subsets without selecting a lucky seed on held-out data.

## 6. Cost-vs-Success Pareto Frontiers (WP5)

`compute_both_frontiers` constructs exact rational non-dominance tables on two explicit axes (cost minimized, $\text{pass@1}$ maximized):
- **Headline Axis (`cost_per_solved`):** $\text{CPS}(c)$ vs $\text{pass@1}(c)$.
- **Diagnostic Axis (`mean_task_cost`):** $\bar{m}(c)$ vs $\text{pass@1}(c)$.

Series with undefined cost (e.g., `zero_expected_solves` on `cost_per_solved`) receive `status = "undefined_cost"`, `is_on_frontier = False`, and never dominate or get dominated by valid points. Exact rational coordinate ties share a deterministic `tie_group_id`.

## 7. Observable-Only Policies and Train-Only Selection (WP6)

- **Strict Boundary (`evaluate_policy`):** Accepts **only** `ObservableSignals` (`has_patch`, `visible_tests_pass`, `hit_step_cap`, `no_command_rate`, `agent_self_reports_done`). Passing a `NormalizedRecord` or dictionary raises `TypeError`, preventing hidden test outcomes, scorer status, or costs from leaking into routing decisions.
- **`None` and Threshold Semantics:** `visible_tests_not_true` fires when `visible_tests_pass` is `False` or `None`; `visible_tests_is_false` fires only when `False`; `visible_tests_is_none` fires only when `None`. `no_command_rate_gt` uses strict `>` (`Fraction(str(rate)) > threshold`), whereas `no_command_rate_gte` uses `>=`.
- **Train-Only Selection (`select_policy_on_train`):** Rejects any panel containing `held_out` records. Evaluates $1 \dots 128$ caller-supplied candidate policies on `train`, filters to candidates achieving $\text{pass@1} \ge \text{min\_success\_floor}$, and minimizes `expected_total_cost_nanos` with deterministic tie-breaking: (1) lower `expected_total_cost_nanos`, (2) higher `pass_at_1`, (3) lexicographically smaller canonical `policy_hash`. Returns an immutable `FrozenPolicySelection` recording train dataset/input/plan/candidate hashes.

## 8. Cold-Restart Cascade Composition and Trigger Diagnostics (WP7)

A cold-restart cascade first executes configuration $A$. If the observable policy triggers ($e_{t, r_A} = 1$), $A$'s workspace is discarded and configuration $B$ starts from the original repository snapshot. Both runs' costs are charged on escalation, and $B$'s outcome **replaces** $A$'s outcome (never OR'd).

Across $k_A$ seeds of $A$ and $k_B$ seeds of $B$ on task $t$, independent uniform seed selection yields the exact analytical cross-product:

$$p_{\text{cascade}, t} = \frac{1}{k_A} \sum_{r_A \in S_A} \left( (1 - e_{t, r_A}) y_{A, t, r_A} + e_{t, r_A} \bar{y}_{B, t} \right), \qquad \bar{y}_{B, t} = \frac{1}{k_B} \sum_{r_B \in S_B} y_{B, t, r_B}$$

$$m_{\text{cascade}, t} = \frac{1}{k_A} \sum_{r_A \in S_A} \left( \text{cost}_{A, t, r_A} + e_{t, r_A} \bar{c}_{B, t} \right), \qquad \bar{c}_{B, t} = \frac{1}{k_B} \sum_{r_B \in S_B} \text{cost}_{B, t, r_B}$$

### Post-Hoc Trigger Confusion Diagnostics

Defining $A$-unsolved ($y_{A, t, r_A} = 0$) as the positive class:
- $\text{TP}$: escalated ($e = 1$) and $A$ unsolved ($y_A = 0$)
- $\text{FP}$: escalated ($e = 1$) and $A$ solved ($y_A = 1$)
- $\text{FN}$: not escalated ($e = 0$) and $A$ unsolved ($y_A = 0$)
- $\text{TN}$: not escalated ($e = 0$) and $A$ solved ($y_A = 1$)

$$\text{Precision} = \frac{\text{TP}}{\text{TP} + \text{FP}} \;\;(\text{undefined if } \text{TP}+\text{FP}=0), \qquad \text{Recall} = \frac{\text{TP}}{\text{TP} + \text{FN}} \;\;(\text{undefined if } \text{TP}+\text{FN}=0)$$

Both micro-weighted counts (over all $n \cdot k_A$ declared $A$ runs) and equal-task-weighted rates are reported alongside `harmed_a_runs_count` (escalated $A$-solved runs where $\bar{y}_{B, t} < 1$).
